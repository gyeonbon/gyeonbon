# 블라인드 티칭 챌린지

**아는 것과 가르치는 것은 다르다!**

고등학교 교육학과 진로체험을 위한 실시간 웹 게임입니다. 교사 한 명이 수업 세션을 열고, 학생 18~19명이 4개 모둠에서 설명자와 학습자 역할을 경험합니다. 설치·회원가입 없이 별명으로 참여하며, 실명·이메일·전화번호를 요구하지 않습니다.

참고 게임의 규칙을 바탕으로 새로운 교육용 화면과 기능을 구현했습니다. 원본 사이트의 코드·로고·이미지·디자인 자산은 사용하지 않습니다.

## 로컬 실행

Node.js 22 이상과 npm이 필요합니다.

```sh
npm ci
npm run build
npm start
```

기본 주소는 `http://localhost:3000`입니다. 개발 서버는 `npm run dev`로 실행합니다. Vite 화면과 Node API 서버가 함께 실행되며, 개발용 화면은 `http://localhost:5173`입니다.

```sh
npm run check
npm test
```

`npm run check`는 프론트엔드와 서버의 정적 검사를, `npm test`는 게임 규칙·권한·비공개 데이터·동기화·복구 관련 서버 테스트를 실행합니다. 테스트는 로컬 HTTP 포트를 사용합니다.

학생 스마트폰의 `localhost`는 교사 PC를 뜻하지 않습니다. 실제 수업에서는 [배포 안내](docs/DEPLOYMENT.md)에 따라 **모든 학생이 접속할 수 있는 HTTPS 주소**를 준비한 후, 그 주소에서 수업을 생성하세요.

## 수업 진행

1. 첫 화면에서 **선생님, 수업 열기**로 세션을 만듭니다. 생성된 6자리 코드·학생용 링크·QR코드를 공유합니다.
2. 학생은 별명을 정하고 입장합니다. 교사는 학생을 4개 모둠에 배정하거나 학생이 직접 모둠을 선택하게 할 수 있습니다. 각 모둠은 최대 5명입니다.
3. 모둠별 설명자를 직접 지정하거나 무작위로 선택합니다. 모든 모둠이 준비되면 교사가 동시에 시작합니다.
4. 설명자는 30초 안에 비공개 제시어 5개 중 하나를 선택합니다. 다른 학생에게는 제시어가 전달되지 않습니다.
5. 설명을 듣는 학생은 그림을 그립니다. 색·굵기·지우개·실행 취소·전체 지우기를 사용할 수 있으며, 그림은 진행 중 자동 저장됩니다.
6. 기본 3번의 질문 기회에 질문과 답변을 주고받습니다. 답변 시간은 20초, 답변 뒤 수정 시간은 10초입니다. 교사가 질문 횟수를 변경할 수 있습니다. 텍스트 진행과 교실에서 직접 말하는 진행을 선택할 수 있습니다.
7. 마지막 20초에 정답을 한 번 제출합니다. 제출 후 변경할 수 없고, 정답 판정은 띄어쓰기를 무시합니다.
8. 정답·설명자·각자의 그림과 제출 답을 갤러리로 비교합니다. 결과는 15초 이상 공개하며 교사가 시간을 연장하거나 그대로 유지할 수 있습니다.
9. **교수법 돌아보기**에서 설명이 다르게 이해된 이유를 나누고, 구체성·설명 순서·이해 확인의 세 원칙을 확인합니다. 시간이 남으면 2차 도전에 참여합니다.

2차 도전의 정답률은 제시어 난이도의 영향을 받습니다. 결과를 교수법의 효과에 대한 인과적 증거로 해석하지 않고, 설명 방식의 변화와 학생 소감을 함께 살펴보도록 구성했습니다.

## 교사용 기능

- 학생 참여·연결 상태와 모둠 편성을 확인하고 전체 모둠을 함께 시작
- 제시어 난이도, 질문 횟수, 설명 시간, 텍스트/교실 진행 방식 설정
- 서버 기준 타이머 일시정지·재개, 모둠별 진행 상태 확인
- 필요한 경우 게임을 종료하고 결과 공개
- 모든 모둠의 갤러리를 큰 글씨 발표 화면으로 표시하고 이미지로 저장
- 1차·2차 결과와 학생의 돌아보기 답변 비교

학생은 교사 권한을 가진 요청을 실행할 수 없습니다. 교사 관리 권한은 수업 생성 시 발급된 무작위 토큰으로 보호하며, 같은 브라우저에서 화면을 다시 열어 이어갈 수 있습니다. **교사 접근 정보는 학생용 초대 링크에 포함되지 않습니다.** 공유할 때는 대시보드의 학생용 링크·QR코드만 사용하세요.

다른 교사 기기에서 이어가야 한다면 대시보드의 **교사 복구키 저장**으로 받은 JSON 파일을 선생님만 보관하고, 첫 화면의 **선생님 복구키로 이어가기**에서 불러오세요. 이 파일은 관리 권한을 가지므로 학생에게 공유하면 안 됩니다.

## 검증 기록과 브라우저 테스트

- `npm ci`를 이용한 lockfile 설치와 `npm run build` 프로덕션 빌드를 확인했습니다.
- 서버 통합 테스트 6개가 통과했습니다. 19명 동시 입장, 교사 포함 20개 SSE 연결, 모둠별 비공개 데이터, 정답 1회 제한, 질문·답변·수정 중 그림 저장, 일시정지, 결과 유지·연장, 2차 도전, 디스크 복구를 검사합니다.
- 독립된 Chromium 프로세스 2개와 브라우저 컨텍스트 20개로 교사 1명·학생 19명의 실제 UI 흐름을 검증했습니다. 5·5·5·4명 편성, 터치 그림, 새로고침 복원, 질문·답변, 15개 학생 그림 공개, PNG 저장, 발표 화면, 소감 저장과 2차 도전 준비가 통과했습니다. JavaScript 페이지 오류는 없었습니다.
- 별도 브라우저 검사로 1·2차 도전을 모두 완료하고, 두 시도의 그림과 설명 전략이 비교 화면에 표시되는 것을 확인했습니다.

브라우저 검증을 재실행하려면 서버를 켠 뒤, Python의 `playwright` 패키지와 로컬 Chromium이 있는 환경에서 다음을 실행합니다. 이는 개발 검증용 선택 의존성이며 웹 게임 실행에는 필요하지 않습니다.

```sh
# 별도 터미널에서 npm start 실행 후
CHROMIUM_PATH=/usr/bin/chromium python3 test/browser_smoke.py
# 다른 서버 주소를 검사하려면 BASE_URL=https://실제주소 를 함께 지정합니다.
```

스크린샷과 결과 PNG는 Git에서 제외된 `test-results/`에 생성됩니다. 자동화는 Chromium과 스마트폰 에뮬레이션으로 수행했으며, 실제 iPhone·Android 및 학교 Wi-Fi에서의 검증이나 공개 배포를 대신하지 않습니다.

## 환경변수

외부 API 키, Supabase 계정, 데이터베이스 계정은 필요하지 않습니다. QR코드는 앱 안에서 생성합니다.

| 이름 | 기본값 | 용도 |
| --- | --- | --- |
| `HOST` | `0.0.0.0` | 서버가 수신할 주소 |
| `PORT` | `3000` | HTTP 포트. 호스팅 서비스가 주입한 값을 사용 가능 |
| `PUBLIC_ORIGIN` | 미설정 | 배포한 사이트의 정확한 외부 출처. 예: `https://your-school-game.onrender.com` |
| `DATA_DIR` | `.data` | 세션 복구용 비공개 스냅샷을 보관할 디렉터리 |

배포 서비스의 환경변수 설정에서 값을 넣으세요. 로컬에서는 [.env.example](.env.example)을 `.env`로 복사한 뒤 Node의 환경파일 옵션으로 실행할 수 있습니다.

```sh
node --env-file=.env server.mjs
```

`.env`는 커밋하지 마세요. `PUBLIC_ORIGIN`을 개발 중인 화면과 다르게 설정하면 정상적인 요청도 차단될 수 있습니다. 개발 중에는 비워두고, 실제 배포에서 공개 HTTPS 출처를 지정하세요.

## 저장·재접속과 데이터 수명

- 새로고침·일시적인 연결 끊김 뒤에는 같은 브라우저의 참여 정보로 재접속합니다. 수업 중 브라우저 데이터를 지우거나 시크릿 창을 닫으면 해당 정보가 사라질 수 있습니다.
- 세션과 그림은 서버 메모리에서 처리하고 `DATA_DIR`에 스냅샷을 저장합니다. 실행 중인 수업을 복구하면 타이머는 일시정지 상태로 시작합니다. 교사가 상태를 확인한 뒤 재개하세요.
- 서버 재시작 복구를 사용하려면 `DATA_DIR`가 유지되어야 합니다. 임시 파일시스템을 사용하는 호스팅에서는 재배포·재시작 후 데이터가 없어질 수 있습니다.
- 세션 데이터에는 별명·그림·제출 답·돌아보기 답변과 참여 토큰이 포함됩니다. 저장 디렉터리는 서버 전용이며 웹에서 제공하지 않습니다. 복구 파일을 학생에게 공유하거나 공개 저장소에 커밋하지 마세요.
- 장시간 비활성 세션은 6시간 보존 기한에 따라 정리됩니다. 수업이 끝나면 교사가 세션을 종료하고 필요한 결과 이미지만 저장하세요. 서버를 중지한 뒤 `DATA_DIR`의 파일을 삭제하면 로컬 복구 사본도 제거할 수 있습니다.
- 여러 서버 인스턴스가 같은 수업을 분담하는 구조는 지원하지 않습니다. 실제 운영은 **단일 Node 인스턴스**로 실행합니다.

## 11월 4일 수업 운영 예시 · 10~15분

| 시간 | 활동 |
| --- | --- |
| 0~2분 | QR 입장, 4개 모둠 편성, 역할과 비공개 규칙 확인 |
| 2~6분 | 1차 도전: 선택 → 설명·질문 → 정답 제출 |
| 6~9분 | 그림 비교와 교수법 돌아보기, 좋은 설명의 3원칙 |
| 9~13분 | 시간이 허락하면 2차 도전 |
| 13~15분 | 설명의 변화·소감 공유, AI로 학습 도구 만들기 활동 안내 |

사전 점검에서는 교실에서 사용할 **학교 Wi-Fi와 실제 학생용 iPhone/Android**로 QR 열기, 터치 그리기, 한글 입력, 새로고침을 확인하세요. 자동화된 브라우저 검증은 학교 Wi-Fi의 접속 정책이나 물리적인 기기 검증을 대신하지 않습니다.

## 배포

[실제 웹사이트로 배포하기](docs/DEPLOYMENT.md)에 Render·Docker·Nginx 설정과 수업 전 점검 절차를 정리했습니다. 이 저장소를 작성했다는 사실만으로 공개 배포와 학교망 접근이 완료된 것은 아닙니다.
